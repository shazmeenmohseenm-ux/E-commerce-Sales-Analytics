1.Project Introduction :  
1. The E-Commerce Sales Analytics project focuses on analyzing sales performance, customer behavior, product performance, and business profitability using real-world e-commerce data.


2. The project uses five CSV files containing information about sales transactions, customers, products, orders, and dataset statistics. The data is processed through an ETL pipeline to ensure that it is clean, consistent, and suitable for further analysis.


3. The ETL process includes extracting data from CSV files, performing data quality      checks, handling missing values, standardizing data types, and saving the transformed datasets for downstream analysis and dashboard development.


4. The final objective is to prepare reliable datasets that can be used to develop meaningful business insights and support data-driven decision-making.


5. Git and GitHub are used for version control, project documentation, and maintaining a structured history of project changes. 
2.Business Problem Statement :

products, sales channels, regions, marketing campaigns, payment methods, and
fulfillment operations.

performance using raw transactional data becomes increasingly difficult.
3. Management needs to understand where revenue and profit are being generated,
which customers and products contribute the most value, which channels and
marketing activities are effective, and where operational problems such as returns,
cancellations, and delivery delays are occurring.
Currently, the presence of multiple dimensions within the e-commerce data makes
It is challenging to obtain a unified view of business performance. Without proper

that converts raw transactional data into actionable business insights through
structured data modeling, KPIs, analytical measures, and interactive reporting

5.Order Date & Order Time: 
138,116 missing values were identified in both order_date and order_time. The missing values occur across multiple order statuses and sales channels, including completed orders. No alternative date/time field was available in the dataset to reliably recover these values. Therefore, the missing dates and times were retained as blank values rather than statistically imputed, to avoid introducing inaccurate temporal information. 
6.Delivery Days & Estimated Delivery Days: 
Both columns contain 24,557 missing values. The missing values occur only for Returned, Cancelled, and Pending orders. Since delivery duration is not applicable or may not yet be available for these order statuses, the missing values were retained as blank rather than imputed. No records were removed. 
7.Return Reason: 
The return_reason column initially contained 128,654 missing values. These records corresponded to orders that were not returned. The missing values were therefore replaced with No Return. Existing returned orders contained specific return reasons such as Wrong Product, Damaged Product, Size Issue, and Defective Product. After transformation, no missing values remained.
8.Customer Rating : 
The customer_rating column contains 24,557 missing values. These missing values occur only for Returned, Cancelled, and Pending orders, while completed orders have ratings available. Since the missing values indicate that no rating was available, they were retained as blank rather than replaced with a statistical value such as mean or median. 
9.Review Sentiment: 
The review_sentiment column contains 24,557 missing values. These records correspond to Returned, Cancelled, and Pending orders. Since no customer review/sentiment is available for these records, the missing values were retained rather than assigning an assumed sentiment. 
10.Customer Review: 
The customer_review column contains 24,557 missing values. These records correspond to Returned, Cancelled, and Pending orders. Since no customer review was available for these records, the missing values were retained as blank rather than replacing them with assumed text. 
11.Campaign Name: 
The campaign_name column contained 83,233 missing values across all marketing channels. Existing campaign values included Default_Campaign and several specific campaign names. However, Default_Campaign was used only for selected marketing channels and therefore could not reliably represent all missing campaign values. The missing values were retained as blank to avoid assigning incorrect campaign information. 
12.Coupon Code: 
The coupon_code column contained 110,502 missing values. Missing coupon codes were observed across different payment statuses and were also associated with both zero and non-zero discount amounts. Therefore, the missing values could not reliably be interpreted as No Coupon. The missing values were retained as blank to avoid making unsupported assumptions about coupon usage.

Machine Learning — Customer Segmentation
1. Overview
As part of the E-Commerce Sales & Customer Analytics project, Machine Learning was implemented to segment customers based on their purchasing behavior, revenue contribution, profitability, order value, and product-return behavior.
The objective of customer segmentation is to identify groups of customers with similar characteristics so that the business can develop targeted marketing, retention, loyalty, and customer-value strategies.
The selected Machine Learning technique is K-Means Clustering, an unsupervised learning algorithm.
ML Objective
The primary objective is:
To segment customers into meaningful groups based on their purchasing and behavioral characteristics and translate those clusters into actionable business segments.
The final solution segments 24,911 customers into 5 customer groups.

7. Feature Scaling
Because the selected features have very different numerical ranges, feature scaling was required before applying K-Means.
For example:
* Total Sales may be in thousands
* Total Orders may be single digits
* Return Rate is a percentage
* Profit Margin is a percentage
Without scaling, large numerical features could disproportionately influence the distance calculation.
Standardization was therefore applied using StandardScaler.
“from sklearn.preprocessing import StandardScaler


scaler = StandardScaler()


X_scaled = scaler.fit_transform(X)”
The scaled data was then provided to the K-Means algorithm.

2. Project Overview
The objective of this project is to analyze e-commerce order data and build a machine learning system to predict whether an order is likely to be returned.
The project combines exploratory data analysis, business analysis, feature engineering, data leakage detection, data preprocessing, and machine learning classification.
The analysis phase was performed using data analysis techniques and Excel-based business analysis, while the prediction phase was implemented using Python and machine learning.
The primary machine learning algorithm selected for prediction is XGBoost, a supervised learning algorithm based on gradient-boosted decision trees.
3. Business Problem
Product returns are an important challenge for e-commerce businesses.
A high number of returns can result in:
* Additional shipping and reverse-logistics costs
* Inventory management problems
* Reduced profit margins
* Increased operational workload
* Customer dissatisfaction
* Additional product handling and processing costs
Therefore, the business needs a way to identify orders that have a higher probability of being returned.
Business Objective
The objective is to develop a predictive system that can answer:
"Given the information available when an order is placed, how likely is that order to be returned?"
The prediction can help businesses identify high-risk orders and support better operational and customer-management decisions.

10. Important Leakage Findings
Several features were explicitly investigated rather than removed without evidence.
1.Customer Order Count
customer_order_count was found to represent the customer's total order history rather than the number of orders completed before the current order.
For example, the same total count appeared across multiple historical orders for the same customer.
Therefore:
Decision: Remove
2.Is Repeat Customer
is_repeat_customer was True even on the first recorded order of some customers.
This indicates that it was likely based on complete customer history.
Therefore:
Decision: Remove
3.Customer Type
The first order of many customers was already classified as Loyal or Returning.
This is inconsistent with an order-time definition of customer type.
Therefore:
Decision: Remove
4.Payment Status
The return relationship showed that returned orders had:
payment_status = Refunded
This occurs after the return process and directly reveals the outcome.
Therefore:
Decision: Remove
5.Loyalty Features
Returned orders had:
loyalty_points_earned = 0
loyalty_points_redeemed = 0
The perfect separation from the target indicated that these fields were not safe for prediction.
Therefore:
Decision: Remove
6.Discount Amount
Returned orders had:
discount_amount = 0
while non-returned orders contained actual discount values.
Because of this suspicious separation, the feature was excluded from the predictive model.

Why XGBoost was selected

* The features can interact with each other.

* It is well suited for predictive modeling on structured datasets.

Number of boosting trees.

Customer Segmentation Analysis 
1. Project Overview :
Customer Segmentation is an analytical approach used to divide customers into different groups based on similarities in their purchasing behaviour, transaction patterns, and profitability.
In an e-commerce business, customers do not behave in the same way. Some customers purchase frequently, some place high-value orders, some contribute higher sales, and others may generate lower profits.
Understanding these differences helps businesses make better decisions regarding marketing strategies, customer retention, promotional campaigns, and profitability improvement.
In this project, customer segmentation was performed using the K-Means clustering algorithm. Customers were grouped into five clusters based on selected purchasing and profitability-related features.
The results were then integrated into Power BI to develop an interactive Customer Segmentation Analysis dashboard.
2. Business Problem :
The e-commerce business has a large customer base, but treating every customer equally may not be an effective business strategy.
Without proper customer segmentation, the business may face difficulties in:
* Identifying high-value customers.
* Understanding different customer purchasing behaviours.
* Recognizing customers who contribute higher sales and profits.
* Identifying customers with higher order values.
* Developing targeted marketing and customer retention strategies.
* Understanding how different customer groups contribute to total product quantity purchased.
Therefore, the business requires a structured approach to group customers according to their purchasing patterns and profitability.
3. Project Goal : 
The main goal of this project is to identify different customer groups using machine learning and analyse their purchasing behaviour and business contribution through Power BI.
The analysis aims to help the business understand:
* How customers are distributed across different segments.

* Which segments have higher average order values.

4. Methodology – Customer Segmentation Using K-Means
1. What Is K-Means Clustering?
K-Means is an unsupervised machine learning algorithm used to group similar data points into clusters.
In customer segmentation, each customer is represented by a set of numerical features.
The algorithm groups customers with similar feature patterns into the same cluster.
Customers belonging to different clusters have relatively different purchasing or profitability characteristics.
2. Data Standardization :
Before applying K-Means, the selected numerical features were standardized using StandardScaler.
Standardization is important because the selected features have different scales.
For example:
* Total Sales may have values in thousands.
* Total Orders may have smaller numerical values.
* Profit Margin Percentage may have a different numerical range.
Without standardization, features with larger numerical values could have a greater influence on the distance calculations.
StandardScaler transforms the features so that they are measured on comparable scales.
3. Selecting the Number of Clusters :
The Elbow Method and Silhouette Score were used to evaluate the appropriate number of clusters.
Elbow Method:
The Elbow Method evaluates the within-cluster sum of squared distances for different cluster counts.
The objective is to identify a point where increasing the number of clusters provides diminishing improvement.
Silhouette Score:
The Silhouette Score evaluates how well customers fit within their assigned clusters compared with neighbouring clusters.
A higher score generally indicates better-defined clusters.
Based on the clustering evaluation, five clusters were selected for the analysis.
4. Final Clustering :
The K-Means algorithm assigned each customer to one of five clusters:
* Cluster 0
* Cluster 1
* Cluster 2
* Cluster 3
* Cluster 4
These cluster numbers are identifiers generated by the algorithm. They do not represent rankings.
5. Cluster Profiling :
After assigning customers to clusters, customer features were grouped by cluster and their mean values were calculated.
This profiling step helps understand the characteristics of customers belonging to each cluster.
The resulting cluster profile was imported into Power BI for visualization.
